## Research Protocol

Use this whenever implementing Thai compliance behavior, statutory reports, receipt layouts, filing calendars, payroll/tax calculations, DBD/TFRS output, or current third-party APIs.

1. Prefer official Thai RD, DBD, SSO, Customs, BOT, TFAC/TFRS, and government sources.
2. Use secondary/accounting-firm sources only to interpret or cross-check; do not make them sole authority for legal facts.
3. Capture exact source URL, retrieval date, and the rule applied in the relevant phase doc or `_ai_context` note.
4. If source text is ambiguous, implement conservative accountant-review workflow rather than a false automatic decision.
5. For library/framework/API docs, use `ctx7` per `AGENTS.md`; do not rely on memory for current API syntax.

## Standard Test Gate

Run narrower suites during inner loops, but before marking any phase complete run:

```bash
pnpm tsc --noEmit
pnpm test
pnpm test:db
pnpm test:e2e
```

Important:

- DB suites share/reset the same test database; run DB suites serially unless the suite is explicitly isolated.
- Current `CLAUDE.md` commit gate is stricter than this phase gate: before committing, run `pnpm build && pnpm test && pnpm lint` and record the result.
- Passing route smoke is not owner walkthrough completion. Keep owner-test-plan execution separate from automated Playwright evidence.

Add phase-specific checks:

- DB migrations apply cleanly from empty database.
- Full export includes new source-of-truth tables and omits retired active tables.
- Playwright route smoke covers every new route.
- At least one end-to-end workflow test covers the main owner path.
- Filing/payment/posting flows include negative tests for tenant mismatch, locked period, filed-source mutation, and stale/replayed actions.

## Stop / Escalate Conditions

- Official source contradicts current phase assumptions.
- CPA/DBD/Builder validation is required before safe implementation.
- A remaining item requires new feature/behavior implementation and no user-approved design exists yet. The local brainstorming gate blocks unattended implementation of new features; prepare a design and wait for approval before coding.
- A migration would destroy data not explicitly declared obsolete in an active cutover plan.
- The UI can render but cannot complete the core workflow end to end.
- Tests pass only by weakening accounting/tax invariants.
